# drawings/ — перерисовка плана с картинки в чертёж в мм (DWG + PDF)

Метод, которым был сделан «План 1-го этажа — размеры помещений» (редакция 2). Задача — взять
растровое изображение плана (скриншот, скан), снять с него геометрию в метрах и выпустить чистый
чёрно-белый чертёж в миллиметрах: размеры всех помещений, площади, экспликация, штамп; файлы DWG и PDF.

Это то, что переносится в исполнителя чертежей на сервере E15. По решению Олега берётся **только
метод второй части**: увеличение исходника ×3 и разбор крупным планом с координатной сеткой.
Ранние подходы (первый чертёж в футах со скана 1972 г. и первая редакция этого плана) сюда
сознательно не включены.

## Быстрый старт

```bash
sudo bash drawings/install_system.sh          # apt + LibreDWG в /opt/libredwg (+ libdxfrw)
python3 -m venv .venv && . .venv/bin/activate
pip install -r drawings/requirements.txt
export LIBREDWG_PREFIX=/opt/libredwg
export LIBDXFRW_DWG2DXF=/opt/src/libdxfrw/build/dwg2dxf/dwg2dxf   # необязательно
bash drawings/run_example.sh                  # результат: drawings/out/plan2_1st_floor_mm.{pdf,dwg}
```

## Что было на входе

- **Тип:** JPEG, 1280 × 1101 px, RGB — скриншот плана 1-го этажа офисного здания из CAD-программы.
- **Качество:** около 25 мм на пиксель. Есть артефакты JPEG, линии толщиной 1–3 px.
  Цветная разметка: перегородки с заливкой «охра», новые стены красные, бетон серый со штриховкой.
  Много лишнего для нашей задачи: маркеры разрезов и фасадов (треугольники), марки дверей и окон
  (оранжевые кружки WD-02, W-1), оси, обозначения витража CW-1ST FL-xx.
- **Размеры на исходнике:** подписан только шаг осей **7,40 м**. Есть несколько местных подписей:
  2.3 (серверная), 2.65 и 2.79 (лестница), 4.10 и 1.38 (марши). Всё остальное снимается по масштабу.
- **Пример:** `examples/input/plan2_1st_floor_source.jpg`.

## Метод по шагам

### 0. Подготовка исходника
- PDF-скан: вынуть растр без пересжатия: `pdfimages -png scan.pdf img` (poppler-utils).
  Превью: `pdftoppm -r 60 -png scan.pdf prev`.
- Скриншот или картинка — как есть.
- Раз в начале смотрим исходник целиком и называем зоны: ядро, санузлы, офисы, фасады.

### 1. «Очистка» = перерисовка, а не фильтрация пикселей
Растр не чистится фильтрами. Чертёж строится заново из примитивов, поэтому шум, артефакты JPEG,
маркеры и чужие обозначения в результат просто не попадают. Переносится только то, что нужно:
оси, колонны, стены и перегородки, витраж, двери, лестница, лифты, сантехника (условно), края террасы.
Цвет исходника используется только для классификации в `measure_walls.py`: охра — перегородки,
красный — новые стены, серый — бетон.

### 2. Увеличение ×3
```bash
python3 tools/upscale.py src.jpg out/src_x3.png --factor 3
```
Lanczos + лёгкая нерезкая маска. Новых деталей не появляется, но край каждой линии становится
плавным, и его положение читается с точностью до трети исходного пикселя (~8 мм). Это главный
урок проекта: в первой редакции геометрия снималась с исходника 1:1 «по центрам линий», ошибки
были 2–5 см на каждой стене, и пропорции помещений поплыли.

### 3. Масштаб и выравнивание (калибровка)
- **Начало координат** — пересечение осей у левой нижней колонны (0, 0); X вправо, Y вверх, метры.
- **Масштаб** — по подписанному шагу осей. Штрихпунктирные оси находятся по проекциям тёмных пикселей
  (строки и столбцы с максимумом). Расстояние между крайними осями 3 × 7,40 = 22,20 м = 888 px,
  отсюда **40,02 px/м** (после ×3 — 120,06 px/м, начало координат в пикселе 1036, 2986).
- **Проверка масштаба** по колоннам (рамка 350 × 400 мм выходит 0,37 × 0,43 м — совпадает)
  и по местным подписям: серверная 2320 мм при подписи «2.3», лестница 2650 мм при «2.65».
- **Горизонтальный шаг осей** не подписан. Он снят по центрам колонн: 7300 + 7400 мм.
- **Выравнивание:** скриншот не повёрнут, оси идут строго по строкам и столбцам пикселей.
  Если исходник повёрнут (скан, фото), его нужно сначала довернуть по линии оси. Для этого
  инструмента пока нет (см. «Открытые вопросы»).

Калибровка передаётся всем инструментам одинаково: `--origin PX PY --ppu K` (см. `tools/calib.py`).

### 4. Чтение геометрии крупным планом
```bash
CAL3="--origin 1036 2986 --ppu 120.06"
python3 tools/grid_overlay.py out/src_x3.png out/crops/wc.png 6.0 10.6 10.0 16.2 $CAL3 --zoom 1.6 --step 0.1
```
Фрагмент зоны (окно в метрах) с сеткой 0,1 м: целые метры красным, половины синим. По таким
фрагментам модель или человек читает координаты: грани стен, петли и ширину дверей, сторону открывания,
ступени, шахты (пример — `examples/process/grid_crop_*.png`). Зоны берутся по 4–6 м, чтобы линии
были крупными.

Точные грани и толщины берутся профилями:
```bash
python3 tools/measure_walls.py out/src_x3.png $CAL3 row 12.8 6.6 9.9  col 8.4 5.0 16.2
# row 12.8: D[6.99..7.03] g[7.03..7.06] D[7.06..7.09] ...  ->  стена x = 7.01…7.23
```
**Правило:** грань стены — внешний край тёмной контурной линии (`D`), а не её центр.
Толщина — расстояние между двумя гранями. Заливка (`g`, `R`, `C`) подтверждает, что это стена.

### 5. Перерисовка (векторизация по координатам)
Автоматической трассировки нет. Геометрия записывается в скрипт плана (`plans/plan2_1st_floor.py`)
как списки прямоугольников в метрах:
- `CONC` — бетон, штриховка ANSI31;
- `PART` — существующие перегородки, контур без заливки;
- `NEW` — новые перегородки, сплошная заливка;
- `GLASS` — стеклянные перегородки, тонкая двойная линия с осевой;
- `OPEN` — проёмы. Они вычитаются из стен через shapely; колонны тоже вычитаются;
- витраж, колонны, двери (петля, ширина, направления «закрыто/открыто»), лестница, лифты, контуры помещений.

Стены объединяются (`unary_union`), поэтому стыки получаются чистыми, без перехлёстов.
Метры переводятся в мм при записи в DXF (`mm()`).

### 6. Контроль наложением — обязательно
```bash
python3 tools/overlay_check.py out/plan.dxf out/src_x3.png out/overlay.png $CAL3 --crop -0.8 5.0 10.0 16.4 out/core.png
```
Линии чертежа рисуются красным поверх осветлённого исходника. Проверка идёт по зонам: ядро, низ,
верх, фасады. Сдвиг больше толщины линии — правка координат и повтор. В редакции 2 линии совпали
по всем зонам (пример — `examples/process/overlay_check_core.png`).

### 7. Слои (все цвета 7 — чёрный)

| Слой | Вес линии, мм | Содержимое |
|---|---|---|
| A-GRID | 0,13 (штрихпунктир AXIS) | оси |
| A-COLS | 0,35 | колонны 350×400, залитые |
| A-WALL-CONC | 0,35 | железобетон, штриховка |
| A-WALL-PART | 0,35 | существующие перегородки (контур) |
| A-WALL-NEW | 0,35 | новые перегородки (заливка) |
| A-WALL-GLASS | 0,18 | стеклянные перегородки |
| A-GLAZ | 0,18 | витраж с импостами |
| A-SLAB | 0,13 | край террасы, парапет, решётки |
| A-DOOR, A-STAIR | 0,18 | двери (полотно + дуга 90°), лестница |
| A-LIFT, A-FIXT | 0,13 | шахты лифтов, сантехника (условно) |
| A-DIMS, A-ROOM-DIMS | 0,13 | общие размеры; размеры помещений |
| A-ROOM-NAME, A-ANNO | 0,18 | названия и площади; прочие надписи |
| A-FRAME | 0,5 / 0,7 | рамка, штамп, таблица |

**Чёрно-белый — по умолчанию** (решение Олега): всё в DXF цвета 7, а `render.py` печатает чёрным
без флага `--color`.

### 8. Размеры
- Размерный стиль: засечки 1,2 мм, текст 2,2 мм (общие) и 1,8 мм (помещения) на бумаге,
  округление до 10 мм, единицы — мм.
- **Помещения — в свету.** В каждом помещении есть ширина и глубина между гранями стен или витража,
  без выносных линий. Узкие помещения (санузлы) получают внешнюю цепочку с выносными линиями.
  Помещения сложной формы — несколько размеров по участкам.
- **Общие размеры:** цепочка по осям (7400 × 3, 7300 + 7400), габариты по витражу.
- **Площади** считаются по контуру помещения (shapely), м² с двумя знаками и запятой.
- **Экспликация:** № / название / размеры в свету / площадь + итог.

### 9. Лист, рамка, штамп
- A2 книжный 420 × 594, масштаб 1:75 (`S = 75`: мм модели на 1 мм бумаги).
- Рамка с полем 20 мм слева и 5 мм с остальных сторон. Штамп 185 × 55 справа внизу.
  Слева внизу экспликация, справа условные обозначения и примечания.
- Положение элементов задаётся в мм бумаги через `PX()`/`PY()`, поэтому лист легко перекомпоновать.

### 10. Шрифты
Текстовый стиль `PLAN` ссылается на `arial.ttf`. В Windows и AutoCAD он есть. При рендере на Linux
ezdxf подставляет доступный шрифт (DejaVu Sans), поэтому нужен шрифт с кириллицей (`fonts-dejavu-core`).

### 11. PDF
```bash
python3 tools/render.py out/plan.dxf out/plan.pdf out/plan@150.png --paper A2P --scale 75
```
ezdxf + PyMuPDF, точный масштаб 1:75 на A2, абсолютные веса линий, чёрный по белому.

### 12. DWG
```bash
python3 tools/dxf2dwg.py out/plan.dxf out/plan.dwg        # нужен LIBREDWG_PREFIX и gcc
python3 tools/check_dwg.py out/plan.dwg out/check.png --paper A2P --scale 75
```
- Формат AutoCAD 2000 (AC1015), единицы мм, кодовая страница ANSI_1251.
- Встроенный в LibreDWG импорт DXF (`dxf2dwg`) на наших файлах не работает (см. ниже). Поэтому DWG
  собирается заново через C API `dwg_add_*`: скрипт раскладывает DXF на примитивы, компилирует
  маленькую C-программу и пишет файл.
- Размеры и штриховки при этом раскладываются на линии, заливки (треугольники SOLID) и текст.
  В DWG размеры выглядят правильно, но как размерные объекты не редактируются.
- Проверка: `check_dwg.py` читает DWG через LibreDWG и libdxfrw (движок LibreCAD), печатает
  число объектов и предупреждения декодера и рисует прочитанное в PNG для сравнения с PDF.

Система: Ubuntu 24.04. Через apt ставились `build-essential autoconf automake libtool pkg-config

## Что получилось хорошо
- **Увеличение ×3, профили и контроль наложением дают точность около ±30 мм** при исходнике
  ~25 мм/px: после наложения все стены совпали с оригиналом.
- **Независимые проверки масштаба сошлись:** шаг осей, размер колонн и местные подписи
  (2.3 → 2320, 2.65 → 2650).
- **Чистый результат:** чертёж собирается из примитивов, поэтому мусора исходника в нём нет;
  стыки стен аккуратные (shapely).
- **Правки дешёвые:** в DXF/PDF размеры живые, а смена типа стены — одна строка в списке
  (так перегородки кабинетов 3, 4 и 6 стали стеклянными).
- **DWG без ошибок** читается двумя независимыми декодерами, и его отрисовка совпадает с PDF.

## Что не получилось или ограничено, и почему
1. **Нет автоматической векторизации.** Координаты стен пишет модель или человек по фрагментам
   с сеткой. `measure_walls.py` даёт точные числа, но список стен составляется вручную. Для голосового
   ассистента это значит: нужен шаг с моделью, которая «видит» картинки, и 2–3 итерации контроля
   наложением.
2. **Первая редакция плана была неточной.** Грани снимались по центрам линий без увеличения,
   ошибка 2–5 см на стену. Исправлено методом выше; первая редакция в папку не входит.
3. **Импорт DXF в LibreDWG (`dxf2dwg`) не работает:** «Invalid DXF code 50 for MTEXT», а после
   обхода — дубли handle у MATERIAL и неполные HATCH. Поэтому DWG пишется через C API.
   Цена — размеры и штриховки в DWG разложены на примитивы.
4. **DWG не открывался в AutoCAD:** AutoCAD в среде нет. Проверено только LibreDWG и libdxfrw.
5. **Кодировка текста в DWG.** Первая версия генератора писала весь не-ASCII текст как
   `\U+XXXX` (7 байт на букву). Длинные русские строки выходили за 255 байт, и LibreDWG при
   обратном чтении обрезала их (это нашлось при подготовке этой ветки). Исправлено: кодовая
   страница ANSI_1251, кириллица 1 байт на букву. DWG в `examples/output` уже исправленный. Символы
   вне 1251 (×, ², ·) остаются в стандартной записи `\U+XXXX`; libdxfrw показывает её как текст,
   а AutoCAD должен показать символ — не проверено.
6. **Заливки в DWG — треугольники SOLID.** В некоторых просмотрщиках между ними видна тонкая
   светлая линия, в печати её нет.
7. **Сеть в облачной среде:** архивы релизов с github.com отдавали 403, ftp.gnu.org был недоступен,
   `git clone` с GitHub работал. На E15 это может быть иначе.
8. **Сантехника и лестница упрощены.** Марки дверей и окон и маркеры разрезов не переносятся.

## Решения Олега
- Единицы — миллиметры. Форматы — DWG и PDF, другие не делать.
- Размеры всех помещений проставлять «по аналогии», то есть по масштабу изображения.
- Анализ исходника делать при увеличении в 2–3 раза и крупным планом. Это метод редакции 2;
  только он переносится на E15.
- Чертёж целиком чёрно-белый, включая контуры стен и размерные линии. Чёрно-белый — по умолчанию,
  если не указано иное.
- Стекло: перегородка между кабинетами 3 и 4 и внутренние стены этих кабинетов; внутренние стены
  кабинета 6.
- Работу сохранить в ветку `drawings-export`, main не трогать.

## Открытые вопросы
1. **Открыть `examples/output/plan2_1st_floor_mm.dwg` в AutoCAD:** шрифт, кодовая страница,
   символы ×/²/·, веса линий.
2. **Нужны ли в DWG редактируемые размеры.** Варианты: писать DIMENSION через API LibreDWG
   (экспериментально) или поставить на E15 бесплатный ODA File Converter (не open source)
   и конвертировать им DXF → DWG с живыми размерами.
3. **Исходники-фото с перспективой и повёрнутые сканы:** нужен шаг выравнивания (поворот или
   перспектива по осям). Сейчас не реализован.
4. **Названия помещений 13 и 16** по исходнику не определить, сейчас «Помещение».
5. **Формат листа, масштаб и штамп.** Сейчас A2, 1:75 и упрощённый штамп. Нужен ли штамп по ГОСТ
   или фирменный — решить.
6. **Репозиторий публичный.** Пример исходника и результата лежат в открытом доступе; если это
   нежелательно, их нужно убрать (и из истории ветки).
